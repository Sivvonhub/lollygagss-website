Meta Pixel (9d60e28, 13 pages) — Deferred pixel init off the critical rendering path. Was inline and synchronous, costing 494ms CPU during initial load per Lighthouse and contributing directly to TBT. Init now fires via requestIdleCallback (2000ms timeout) with a setTimeout(1500) fallback for browsers without it, plus immediate firing on first scroll or touch, behind a once-only guard. PageView still fires exactly once; the noscript pixel fallback untouched. Deliberately not deferred to window.load — load fires ~4-5s on this page and would silently drop PageView for anyone who leaves before then, the same failure mode already suspected for GA4 session undercounting on paid clicks.

Microsoft Clarity (8ea9012, 13 pages) — Same rationale and pattern as the Meta Pixel deferral above (316ms CPU cost, same requestIdleCallback/setTimeout/scroll-or-touch guard).

Exchange rates (67131b9, 6 pages) — Deferred the live exchangerate-api.com fetch to window.load and added a 24-hour localStorage cache so most page loads skip the network call entirely. Refreshed the hardcoded fallback rates (used on every cold load before any live fetch resolves), which were up to ~15% stale — the AUD fallback (0.0000862) had been overstating AUD-displayed prices by roughly 8% against the current live rate (0.0000800).
